# 管理 Ronde

本指南面向为组织运行 Ronde 的人：自托管实例的管理员，以及工作空间（云端或你自己的服务器上）的所有者和管理员。如需安装 Ronde，请先阅读[自托管指南](../self-hosting/README.zh.md)。

## 实例

新实例上创建的第一个账户会成为它的**管理员**。管理员从左上角的工作空间菜单打开**服务器管理**（`/admin`），在那里可以：

- 查看实例中有多少账户、工作空间和会议；
- 选择默认语言，当个人和浏览器都没有要求 Ronde 支持的语言时使用；
- 决定谁可以创建账户；
- 输入或移除许可证密钥。

在此页面保存的值优先于环境变量。每个工作空间自己的设置（成员、角色、安全）仍在该空间的**设置**中。

在云端，服务器由 Ronde 团队运营：没有服务器管理，任何人都可以创建账户，每个工作空间的方案来自其订阅。

### 谁可以创建账户

| 策略 | 谁可以注册 |
| --- | --- |
| 仅限邀请（默认） | 只有被邀请加入工作空间的人 |
| 邮箱域名 | 被邀请的人，以及使用所列域名邮箱的任何人 |
| 开放 | 任何能访问该实例的人 |

同样的选择也可以通过 `SIGNUP_POLICY`（`invite-only`、`domains`、`open`）和 `SIGNUP_ALLOWED_DOMAINS` 设置。

### 许可证密钥

Team 和 Enterprise 功能通过许可证密钥开启，可在服务器管理中填写，或通过 `RONDE_LICENSE` 变量设置（变量优先并锁定该字段）。密钥在服务器上离线校验：不会向任何地方发送数据。页面会显示方案、客户、到期日期和已使用的席位数。

- **人数超过席位**：不会阻止任何操作；页面会提示你更新许可证。
- **已过期**：14 天的宽限期内一切照常运行。之后，付费功能变为只读：已有内容仍可查看，但不能新增。社区版功能永远不受影响。
- `ronde-ce` 镜像仅由开源代码构建，无法读取许可证密钥：如需 Team 或 Enterprise，请使用 `ronde` 镜像。

学校和大学可获得免费的 Enterprise 许可证：请使用所在机构的邮箱写信至 hello@joinronde.com。

### 隐藏付费方案

管理员会在设置中看到关于付费功能的低调提示（会议进行中从不显示）。设置 `RONDE_HIDE_UPGRADE_HINTS=1` 可在整个实例中移除这些提示。

## 工作空间

工作空间汇集一个团队的人员、会议、模板和连接器。任何允许注册的人都可以创建工作空间；一个人可以属于多个工作空间。其设置位于侧边栏的**设置**中：

| 标签页 | 内容 | 谁能看到 |
| --- | --- | --- |
| 常规 | 名称、链接、语言、职位类别、谁可以创建会议、连接器和集成 | 所有人；所有者和管理员可修改 |
| 安全 | 已验证域名、身份提供方、LDAP、SCIM | 所有者和管理员（Enterprise） |
| 角色 | 自定义角色 | 所有者和管理员（Enterprise） |
| 审计日志 | 谁改了什么 | 所有者和管理员（Team、Enterprise） |
| 账单 | 方案和发票 | 所有者和账单角色，云端 |
| 方案 | Team 和 Enterprise 增加的功能及获取方式 | 所有者和管理员，自托管 |

### 角色

每个成员在工作空间中有一个角色：

| 角色 | 可以 |
| --- | --- |
| 所有者 | 所有操作，包括账单和删除工作空间 |
| 管理员 | 除账单和删除外的所有操作；担任每个会议的主持人 |
| 账单 | 套餐、发票和付款方式，仅此而已（云端） |
| 组织者 | 成员的全部权限，并可在仅限管理员时创建会议、邀请人员 |
| 成员 | 查看目录、创建会议（除非仅限组织者和管理员）、保存模板 |
| 访客 | 只能看到受邀的会议 |

会议中的每个人还有一个会议角色：

| 角色 | 可以 |
| --- | --- |
| 主持人 | 主持场次、配置会议、管理会议人员、编辑会议纪要 |
| 联合主持人 | 主持场次和编辑会议纪要，但不能修改会议的设置或人员 |
| 参与者 | 填写自己的进展卡、参加场次、查看历史 |
| 观察者 | 旁观场次并查看历史 |

创建会议的人就是它的主持人。在 Enterprise 中，**自定义角色**为成员和访客添加权限；其会议权限适用于工作空间的所有会议。

### 人员和邀请

**目录**由工作空间的所有会议共享：一个人的姓名、生日（仅日和月）、职位类别以及 GitLab 或 GitHub 账户只需填写一次。可以添加没有账户的人，用于他们不登录的会议；邀请他们会发送一封带有 14 天有效链接的邮件。移除成员会终止其访问权限；其进展卡和历史仍保留在工作空间中。使用 SCIM 时，在你的目录中被停用的人也会以同样方式失去访问权限。

### 离开

每个人都可以在个人资料中添加自己的离开时段（人员管理者可以为任何人添加）：第一天和最后一天、一条备注，以及在此期间由谁主持其负责的会议。离开期间，此人在这些天的场次中被标记为缺席，不会收到提醒，个人资料会显示其返回时间。被指定为代理的人会收到通知，并仅在这些天里以主持人身份主持这些会议。

### 会议之间的间隔

在“常规”标签页中，**两次会议之间的间隔**（无、5、10、15 或 30 分钟）会在每个人的每次会议前后保持空闲。“查找时段”会遵守这一间隔，会议日程也会标出与同一批人的另一个会议靠得太近的日期。

## 登录与单点登录

社区版提供邮箱和密码账户、邮件登录链接、双重身份验证、Google、GitHub 和 Microsoft 账户，以及实例级的一个 OpenID Connect 提供方（`OIDC_*` 变量，见[自托管指南](../self-hosting/README.zh.md)）。

每个人都可以在自己的账户中，于**登录与安全**下管理登录方式：密码、通行密钥（Face ID、Windows Hello、密码管理器或安全密钥）、两步验证，以及在所有设备上退出登录。通行密钥与 `APP_URL` 的域名绑定，该地址必须使用 HTTPS：更换域名后，需要重新添加。必须使用单点登录的地址既不能添加也不能使用通行密钥。

在 Enterprise 中，工作空间的**安全**标签页还提供：

1. **已验证域名。** 添加你的邮箱域名和显示的 DNS 记录，然后进行验证。已验证的域名可以：
   - **接管新账户**：使用该域名邮箱注册的人会以成员身份加入工作空间；
   - **强制单点登录**：其地址只能通过你的提供方登录，不能用密码，也不能用邮件链接。开启前请先确认提供方对你有效。
2. **身份提供方**，OpenID Connect 或 SAML（Okta、Entra ID、Google Workspace、Keycloak……），用于已验证域名的地址。页面会给出需要在提供方一侧填写的重定向 URI 或回复 URL（ACS）以及 entity ID。
3. **公司目录（LDAP 或 Active Directory）。** 人员使用目录密码登录。Ronde 通过服务账户查找他们，并在不保存密码的情况下进行验证。请使用 `ldaps://`，或配合 StartTLS 使用 `ldap://`。
4. **用户配置（SCIM）。** 你的目录（Okta、Entra ID、JumpCloud……）会创建人员、同步其姓名和地址，并在其离开时移除。该标签页提供 SCIM 端点和令牌。

位于带身份验证的反向代理之后的实例，也可以改为信任代理在请求头中传递的地址（`AUTH_TRUSTED_EMAIL_HEADER`）；只有在其他任何途径都无法访问 Ronde 时才这样做。

## 会议

所有者和管理员可以在“常规”标签页中将会议创建限制为组织者和管理员。之后，每个会议都有自己的设置，向其主持人开放：日程、人员和角色、进展卡板块、议程、模块、外观、通知、视频通话和集成。会议可以保存为工作空间模板，不包括其人员、历史和令牌。

会议默认使用其模板的表情符号，显示在菜单中会议名称旁边；主持人可以在“设置 › 外观”中换一个表情符号，或上传图片（标志、团队合影）。

### 临时场次

会议卡片上的**立即开始**会在日程之外马上举行一场：团队会收到通知（铃铛，以及“会议已开始”通知规则），控制台随即打开。该场次的日期为今天；原计划日期保留在日程中。在控制台中开始一个为其他日期准备的场次，效果相同。

### 示例会议

在第一次会议之前，工作区首页会提供一个示例会议：一个由五位虚构成员组成的每周例会，包含一个月的归档会议（会议纪要、统计和行动项）以及一次随时可以开始的会议，全部使用工作区的语言。它用于试用所有功能：不会发送任何内容（没有提醒、邮件、日历事件或通知），不计入席位，不勾选任何入门步骤，也不计入工作区的分析和报告。其页面上的横幅会说明这一点，点击**删除示例**即可将其连同虚构团队永久删除（被添加到其他会议的该团队成员会保留）。其成员在名录中显示为“示例”，无法被邀请。

### 公共假日

在“常规”选项卡中，工作区选择一个国家的公共假日，假日因地区而异时还可选择地区（德国的州、西班牙的自治区等）；新工作区默认使用其时区所在国家的假日。落在这些日子的会议会被跳过：系统会准备下一个日期，提醒和日历随之调整，日程中会标出假日名称。会议可以在其日程中改用其他假日或不跳过任何假日，主持人也仍可保留或改期每一次被跳过的会议。假日数据来自 date-holidays 项目，基于维基百科（CC BY-SA 3.0）。

### 访客链接

在会议设置中，**人员 › 访客链接**会为没有账户的人（客户、董事会、合作伙伴）创建一个秘密链接。它以只读方式实时打开共享屏幕，直到过期（1 到 90 天）或被主持人撤销。链接只在创建时显示一次；Ronde 只保存其哈希值。

### 项目与项目组合

空间的**项目**页面汇集了项目组合：每个项目、主题或工作方向都有一句话介绍、描述、主题、阶段、状态（进展顺利、有风险、遇到困难）、负责人、参与的人、日期和链接。成员可以创建项目；负责人和管理员可以编辑项目。项目页面按会话汇总每次会议对它的讨论，只对能查看这些会议的人显示。

每个项目都可以有徽标，显示在名称旁和会议中它的环节上：在项目页面点击它的标记即可选择图片；没有徽标时，以其颜色显示名称首字母。导入会带来工具中的图片：GitHub 组织的头像、GitLab 项目或 Jira 项目的头像。 可编辑该项目的人可以更换或移除它。

会议在**设置 › 项目**中选择跟进的项目。每个跟进的项目在每个人的进展卡里都有一个标签页，并有一张共享的项目卡：状态和今日要点，由参与项目的人填写。在议程中加入**按项目轮流**环节，每个项目就有自己的轮次，由成员一起发言；没有这个环节时，项目的条目会在每个人的轮次中介绍。**项目组合评审**和**团队与项目**模板默认包含这个环节。使用 Team 版时，仪表板按周显示每个项目的状态、截止日期和没有消息的项目，可导出为 CSV，并在邮件报告中列出需要关注的项目。使用 Enterprise 版时，项目可以归入另一个项目（后者即成为计划，最多三层），可以只对项目成员可见，也可以让成员而不只是负责人编辑。

同一页面上的**导入**可从你的工具带入项目：GitHub 组织的仓库或 GitLab 群组的项目、GitHub 仓库或 GitLab 项目的里程碑（每个命名为“仓库 · 里程碑”）、Jira 项目的史诗，或 Linear 的项目。勾选要带入的项；已在项目组合中的会被识别，每一项只会带入一次。在此输入的令牌仅用于该次导入，不会保存：

- GitHub：公开仓库无需令牌；私有仓库需要能读取它们的细粒度令牌（Metadata，里程碑还需要 Issues）。
- GitLab：公开群组和项目无需令牌；否则需要具有 `read_api` 范围的个人、群组或项目访问令牌。
- Jira：所填邮箱对应账户的 API 令牌（id.atlassian.com › 安全 › API 令牌）。
- Linear：个人 API 密钥。

成员可从 github.com、gitlab.com、Atlassian Cloud 和 Linear 导入；从其他服务器（GitHub Enterprise、自托管的 GitLab、Jira Data Center）导入，以及通过空间设置中保存的工单系统导入，仅限空间管理员。使用 Team 方案时，通过这类工单系统导入，项目每小时保持同步：名称、阶段、日期和进度跟随该工具，工具未提供的内容保持 Ronde 中的设置（仓库提供其名称，归档后标记为“已完成”），进度在保持最新时显示在项目组合的卡片上和会议中。项目页面提供**立即更新**和**停止同步**。点击**停止同步**、工单系统被移除或改为指向另一台服务器时，同步永久停止；空间不在 Team 方案时，同步暂停。工具再也找不到的项（已删除或超出令牌的访问范围）每天重试一次。 已归档的项目在恢复前不会更新。

### 模块

所有主持引导模块都免费：破冰、团队心情、实用度评分、表情反应、举手、致谢、聚光灯、转盘和抽签、生日、声音、限时议题、投票、停车场、决定日志、回顾、计划扑克和异步会议。在会议中关闭的模块会从其控制台、共享屏幕和进展卡中消失；其设置会被保留。

实用度评分会在收尾时请每个人评价会议是否有用（1 到 5 颗星，在自己的屏幕或手机上评分）。至少有 3 个评分后才显示平均分，这样谁也猜不出别人的评分；平均分会写入会议纪要和统计。简短的每日会议、一对一会议和正式机构（指导委员会、理事会、班级委员会、工地例会、病例讨论会、事故复盘）的模板默认关闭此模块。

### 导出

列出内容的页面都可以导出给电子表格：**导出为 CSV** 出现在“行动项”页面（该视图的所有行动项，包括两周前已完成的）、“决定”页面（带搜索和会议筛选）、会议的统计（每次会议一行），以及 Team 方案中的“洞察”表格和项目组合仪表板。会议纪要可在“历史”中下载为 Markdown 或 PDF。文件在 Excel、LibreOffice 或 Numbers 中直接按列打开，并符合使用者的语言（法语、德语、西班牙语、意大利语、葡萄牙语和俄语使用“;”和小数逗号），看起来像公式的文本仍保持为文本。

## 通知

**连接器**是会议可以发布消息的渠道：电子邮件、Matrix（Tchap）、Slack、Microsoft Teams、Discord、Mattermost，或使用 HMAC 签名的 webhook。所有者和管理员在工作空间的“常规”标签页中添加它们。之后，每个会议在其通知设置中选择哪些事件发送到哪个连接器：场次即将开始、已开始或已结束、会议纪要已发布、进展卡提醒、行动项逾期、生日。

每周一 8:00 起（按工作空间时区），每位成员会收到一封**每周周报**：本周的会议及各自进展卡的链接、未完成的待办事项以及收到的点赞。只有在有内容时才会发送；每个人都可以在账户中或通过邮件底部的链接关闭它。自托管实例需要配置 `SMTP_URL`；`RONDE_WEEKLY_PER_RUN`（默认 150）限制每小时发送的邮件数，其余顺延到下一小时。

使用 Team 时，工作流构建器可为每条消息添加条件和你自己的措辞，另有两个连接器通过 Twilio 发送**短信**和 **WhatsApp** 消息：填写 Account SID、发送号码和 auth token。消息会发送到人们在个人资料中填写的手机号码（国际格式，+86…），从不发送给离开中的人。对于 WhatsApp，发送方必须在 Twilio 中获批；在对方未主动发起的对话中，WhatsApp 可能要求使用已获批的消息模板。

**通过邮件填写进展卡**：当实例读取一个邮箱时（`INBOUND_IMAP_URL`，见自托管指南），提醒邮件会说明可以直接回复。每个板块的名称占一行，条目写在下面：这些条目会加入该成员的进展卡（不会替换任何内容），并有邮件确认添加了什么。只有来自提醒收件地址（或其账户地址）的回复才有效，有效期 14 天；观察者和示例会议除外。

**推送通知**：实例配置好密钥后（见自托管指南），每个人都可以从浏览器安装 Ronde（或在 iPhone 上将其添加到主屏幕），并在自己的账户中逐个设备开启通知：实时会议中快轮到自己时、进展卡提醒，以及铃铛中的消息。每种通知都可以关闭，设备也会在那里列出。

## 集成

在 Ronde 中输入的令牌和密钥在保存前会用 `SECRET_KEY` 加密，且不会再次显示。请妥善保管这个密钥：没有它，这些内容将无法再读取。

使用 Google、GitHub、Microsoft 或单点登录的账户的令牌同样会加密，使用 `AUTH_SECRET`。

| 集成 | 位置 | 方案 |
| --- | --- | --- |
| GitLab 和 GitHub：将 issue 和合并请求导入进展卡 | 会议设置 | Community |
| 视频通话：任意链接、Jitsi、BigBlueButton | 会议设置 | Community |
| 为每个会议创建 Zoom、Google Meet 和 Teams 房间 | 工作空间，常规 | Team |
| Google 和 Outlook 日历：将场次写入参与者日历，读取空闲状态 | 工作空间，常规 | Team |
| 从后续行动项创建 Jira、Linear、GitLab 和 GitHub 工单，并同步关闭 | 工作空间，常规 | Team |
| GitHub、GitLab、Jira 和 Linear：将仓库、里程碑、史诗和项目导入项目组合 | 项目 › 导入 | Community |
| 已导入的项目与其工具保持同步：名称、阶段、日期和进度 | 项目 › 导入，通过工单系统 | Team |
| 在共享屏幕、邮件和会议纪要中显示你的徽标 | 工作空间，常规 | Team |
| Slack 应用：私信提醒、在 Slack 中填写进展卡、`/ronde`、用于通知的频道 | 工作空间，常规 | Team |
| Microsoft Teams 应用：私信提醒、在 Teams 中填写进展卡、`ronde`、用于通知的频道 | 工作空间，常规 | Team |
| Notion 和 Confluence：每次会议的纪要发布为页面，并随摘要更新 | 工作空间，常规；然后在会议设置 › 集成中选择 | Team |

### Slack

在 Team 版中，所有者和管理员在“常规”标签页点击**添加到 Slack**，并选择通知频道。之后：

- 进展卡提醒以私信送达，附带**填写我的进展卡**按钮，在 Slack 表单中打开会议的各个板块；答案会保存到
  Ronde，就像在页面上填写的一样；
- 所选频道会成为一个连接器，可直接用于会议的通知规则（纪要已发布、会议即将开始……）；
- `/ronde` 向每个人显示其接下来的会议和未完成的跟进行动，仅本人可见。

通过邮箱识别成员：其 Slack 账号与 Ronde 个人资料必须使用同一个邮箱。未在 Slack 中找到的人仍会收到邮件提醒。
**断开连接**会从 Slack 中移除该应用，并删除发布到其频道的通知规则。在自托管实例上，管理员需先创建实例的
Slack 应用（参见自托管指南）。

### Microsoft Teams

所有者或管理员在“常规”标签页下载适用于 Teams 的 Ronde 应用；Teams 管理员将其上传到组织的应用中并添加到一个团队。Ronde 会在该团队的频道中发布一张卡片：点击 **关联到 Ronde** 会打开 Ronde，在其中选择工作空间。此后，进展卡提醒会通过私信发送给在团队中找到的成员（按邮箱识别），并附带一个将消息变为进展卡表单的按钮；向应用发送“ronde”会列出此人接下来的会议和未完成的行动项；该频道也会成为会议通知规则的一个连接器。将应用从团队中移除，或在 Ronde 中 **取消关联**，即可停止这一切，提醒恢复通过邮件发送。

### Notion 和 Confluence

所有者和管理员在“常规”标签页中添加 Wiki：一个与内部集成共享的 **Notion** 页面（在 notion.so/profile/integrations 创建集成，然后通过 ••• › 连接 把页面共享给它），或一个 **Confluence** 空间，可以在云端（站点、空间键、账户邮箱和在 id.atlassian.com 创建的 API 令牌），也可以在 Data Center 或 Server 上（个人访问令牌）。可选的父页面用于集中存放会议纪要。之后，每个会议在“设置 › 集成”中选择自己的 Wiki：每次归档时，纪要会成为一个以会议日期和会议名称命名的页面，并附有返回历史的链接。修改摘要会更新页面；以前的会议可从历史中发布，发布失败时会说明原因并可重试。示例会议不会发布任何内容。

### AI 助手和转写

使用 Team 时，**AI 助手**会起草场次摘要并建议后续行动项；主持人会在保存前审阅全部内容。它使用 Anthropic API 密钥：实例的密钥（`ANTHROPIC_API_KEY`）或工作空间自己的密钥。

**转写**会把场次中所说的内容逐个发言转成文字。它需要语音转文字服务：OpenAI，或你自己的 Whisper 服务器（Compose 文件中的 `whisper` 配置文件会在同一台机器上运行一个）。每个会议必须在设置中允许转写，录音期间所有人都会看到横幅提示，每个人都可以将自己的发言排除在外。声音在转写完成后立即删除。

## 审计日志

使用 Team 时，**审计日志**标签页会列出最近 90 天内谁在工作空间中改了什么：设置、人员、角色和会议，并可导出 CSV。Enterprise 保留完整历史，并可将每条记录签名后发送到 webhook 连接器，供你的 SIEM 或日志平台使用。

## 备份与升级

Ronde 保存的所有内容都在其 PostgreSQL 数据库中。[自托管指南](../self-hosting/README.zh.md#backups)介绍了如何备份、恢复以及升级到新版本。
